По QuerySet:
Наборы запросов QuerySet вычисляются только в следующих ниже случаях:
• при первом их прокручивании в цикле;
• при их нарезке, например Post.objects.all()[:3];
• при их консервации в поток байтов или кешировании;
• при вызове на них функций repr() или len();
• при вызове на них функции list() в явной форме;
• при их проверке в операциях bool(), or, and или if.
Методы QuerySet:
Метод filter() чтоб сделать фильтрацию набора по каким-то критерям.
Метод exclude() для исключения из набора запросов QuerySet(работать можно в связке с filter).
Метод order_by() используя можно упорядочивать результаты поразным полям.

По умолчанию в каждой модели используется менеджер objects. Этот менеджер извлекает все объекты из базы данных

Про модельных менеджеров:
Зачем нужны модельные менеджеры?

1.Инкапсуляция логики выборки: 
Менеджеры позволяют выделять логику выборки данных в отдельные методы, что делает код более чистым и понятным.
Например, можно создать метод, который возвращает только активные объекты или объекты с определенными характеристиками.

2.Переопределение стандартного поведения: 
Вы можете изменить стандартные методы менеджера (такие как get_queryset()), чтобы адаптировать выборку данных под свои нужды. 
Это особенно полезно, если вам нужно добавить дополнительные фильтры или условия.

3.Улучшение читаемости и повторного использования кода: 
Вместо того чтобы повторять одни и те же запросы в разных частях вашего приложения,
вы можете создать методы в менеджере и использовать их по мере необходимости.

4.Оптимизация запросов: 
С помощью менеджеров можно применять методы, такие как select_related() и prefetch_related(),
чтобы минимизировать количество запросов к базе данных и улучшить производительность.

Представление Django – это просто функция Python, которая получает веб-запрос и возвращает
веб-ответ. Вся логика желаемого ответа находится внутри функции-представления.

Шаблоны URL-адресов позволяют соотносить URL-адреса с представлениями. Шаблон URL-адреса состоит из строкового шаблона, представления и, 
опционально, имени, которое позволяет именовать URL-адрес в масштабе всего проекта.

templates:
Django has a powerful template language that allows you to specify how data is displayed. It is based
on template tags, template variables, and template filters:
• Template tags control the rendering of the template and look like {% tag %}
• Template variables get replaced with values when the template is rendered and look like {{
variable }}
• Template filters allow you to modify variables for display and look like {{ variable|filter }}




Пагинация — это способ разделения контента на несколько страниц, чтобы избежать перегрузки одной страницы большим количеством данных.
В данном случае, в вашем шаблоне используется пагинация для отображения отзывов, и она реализована с помощью стандартных возможностей Django.

Эти поля относятся к объекту page_obj, который является экземпляром класса Page из Django.
Он предоставляется через объект пагинатора и содержит информацию о текущей странице и доступных страницах.
reviews.has_previous: Возвращает True, если есть предыдущая страница.
reviews.has_next: Возвращает True, если есть следующая страница.
reviews.previous_page_number(): Возвращает номер предыдущей страницы.
reviews.next_page_number(): Возвращает номер следующей страницы.
reviews.number: Номер текущей страницы.
reviews.paginator.num_pages: Общее количество страниц.
reviews.object_list: Содержимое текущей страницы (например, отзывы для этой страницы).
